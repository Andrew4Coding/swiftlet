# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`Swiftlet` is a SwiftUI personal-finance tracker (Indonesian Rupiah only) backed by SwiftData with CloudKit sync, plus a share extension and a WidgetKit extension.

- Bundle identifier: `com.andrew4coding.swiftlet.Swiftlet`
- Deployment target: iOS 26.5
- The Xcode project is generated by XcodeGen from `project.yml` (`Swiftlet.xcodeproj` is git-ignored). Run `xcodegen generate` after adding or removing files.

## Architecture

- `Swiftlet/Models` — SwiftData models: `Transaction` (expense / income / transfer), `TransactionCategory` (emoji + colour; `purposeRaw` and `monthlyBudget` stay in the schema for CloudKit but nothing reads or writes them), `Wallet` (user-defined, balance derived from transactions; icon is an SF Symbol in `symbolName`, with legacy `emoji` mapped through `resolvedSymbolName`), `RecurringTransaction`, and the split bill models `SplitBill` / `SplitItem` / `SplitShare` / `SplitPerson` (see below). `MoneySource` is the legacy fixed wallet list, kept only so `WalletMigrator` can link old transactions.
- CloudKit constraints apply to every model: all attributes need defaults or optionals, and every relationship must be optional with an inverse.
- `Swiftlet/Services` — stateless helpers: category seeding and icon suggestion (Foundation Models, with a keyword fallback), wallet migration, recurring scheduling and reminders, import/export.
- `Swiftlet/Services/Transaction` — `PaymentProofReader` runs when an image is shared into Add Transaction (`AddTransactionView(receiptImageData:)`): Vision rows (`ReceiptScanner.recognizeRows`, Cyrillic lookalikes folded to Latin), then keyword rules for the paid total (`PaidAmountDetector`) and the merchant. Foundation Models is a fallback only for what the rules miss, and its amount or merchant is accepted only if it appears in the OCR text. `PaymentCategoryResolver` then classifies the merchant with `TransactionCategoryModel`, then `CategoryClassifier`, never picking Other and never overriding the user's choice (`AddTransactionViewModel.applyDetectedCategory`). The whole read is capped at `PaymentProofReader.detectionLimit` (2 s via `withTimeout`); past it Add Transaction shows "Amount not detected" and drops any late result. The amount goes through `AmountCalculatorViewModel.setAmount` unless the user already typed one. Runs in the app, not the share extension (memory limit). Keep these `nonisolated` except the resolver.
- `Swiftlet/Services/Chat` — Ask Swiftlet (spec 0008), an on-device chat in the Ask tab (`Tab(role: .search)` in `RootTabView`). `ChatSessionFactory` builds a `LanguageModelSession` with five read-only tools in `Tools/` (`SpendingSummaryTool`, `FindTransactionsTool`, `WalletBalanceTool`, `SplitDebtsTool`, `UpcomingRecurringTool`). Tools read through `ChatDataSource` (`@MainActor`, wraps `ModelContext`) into plain `ChatSnapshot` values; `ChatQueries` and `ChatReport` do the filtering, integer-rupiah sums and text, and are the unit-tested part (`ChatQueriesTests`). The model gets explicit `yyyy-MM-dd` dates and never does the maths. `ChatViewModel` streams replies and, on `exceededContextWindowSize`, rebuilds the session with a `ChatHistorySummary` and retries once. The iOS Simulator lacks the model's sensitive-content assets, so real generation fails there (`ModelManagerError 1001`); test answers on a device. Keep these `nonisolated` except `ChatDataSource`.
- `Swiftlet/Services/Split` — split bill logic. `SplitCalculator` does integer-only splitting (shares always sum to the total). `CropGeometry` holds the crop-rectangle maths used by `ReceiptCropView`, `ReceiptScanner` reads the cropped photo with Vision and groups text into rows, `ReceiptParser` turns rows into items and extras, `ReceiptModelParser` is the Foundation Models fallback. `SplitTextParser` and `SplitTextMatcher` turn typed text such as "Andrew beli 2 nasi goreng" into per-person unit claims on items (`SplitItem.assigneeUnits`), with `SplitTextModelMatcher` only suggesting matches. Keep these `nonisolated`, since the project defaults to MainActor.
- `Swiftlet/AppIntents` — Siri and Shortcuts. `AddTransactionIntent` asks for the amount, then the title, and infers the category from the title (`TransactionCategoryModel`, the bundled Core ML text classifier, then `CategoryClassifier` (Foundation Models), then keywords, then "Other"); `TransactionEntity`/`CategoryEntity` back the queries.
- `Swiftlet/ViewModels` — `@Observable` view models.
- `Swiftlet/Views` — feature folders (Home, Add, Transactions, Split, Wallet, Recurring, Category, Account) plus shared `Components` (`AppTheme`, `FormField`, badges).
- `Swiftlet/DesignSystem` — mint ink design system matched to the app icon: colour, typography and elevation tokens, `DesignSystemTheme` in the environment (applied at the root with `.designSystemTheme()`), `DSButton`/`DSButtonStyle`, `DSSurface` (`.dsSurface()` replaces the old `.card()`), and Figma-mapped stubs. `AppTheme.accent/income/expense` forward to `ColorToken`. The UI is plain: no gradients or materials; filled mint controls always use ink labels. Toolbar plus buttons use `ToolbarAddButton` (flat prominent mint, no glass); swipe actions are icon-only, with `Image.swipeIcon` for ink icons on mint; use `ContrastColor.foreground(onHex:)` for text on arbitrary colours. Recurring rules are added in two steps (amount keypad, then details) like transactions. Emoji are only for category icons; everything else uses SF Symbols.
- The Account tab has a Manage section (Categories, Recurring, Wallets) pushing `CategoryListView`, `RecurringListView` and `WalletsView`. Categories edit through `CustomCategoryEditorView` (`Views/Category`); deleting one leaves its transactions uncategorised. Home keeps its Upcoming and Wallets shortcuts.
- `SwiftletMenuBar` also compiles `DesignSystem/Tokens/Colors` because `AppTheme` reads `ColorToken`; keep those files cross-platform.
- `SwiftletWidgets` compiles a few app files directly (see `project.yml`), so keep those free of app-only dependencies.

The split sheet opens `ReceiptCameraView` (AVFoundation, custom shutter) inline as its first screen, then crops, then shows a button-free processing state while `ReceiptScanner` runs. The People step can add names from `ContactPicker` (`CNContactPickerViewController`, no Contacts permission needed). Marking a person paid and sending a reminder are swipe actions on the split detail; there are no part payments. A saved split is edited in place: `SplitBillViewModel(editing:)` rebuilds the draft from the bill (participant ids are the share keys), and `save` updates the bill, its expense and its shares, keeping recorded payments. A split bill keeps the receipt photo on `SplitBill.receiptImageData` (older bills fall back to the transaction's photo) and shows it through `ReceiptPreviewButton` on the items and people steps and in the detail, with `ReceiptThumbnail` in the Splits list. An item can be shared by units (`SplitItem.assigneeUnits`, parallel to `assigneeKeys`, empty means equal sharing).

A split bill saves the user's share as the paying `Transaction` (so stats stay honest) and keeps the rest as `SplitShare`s owed to them. `Wallet.balance` subtracts the outstanding shares of splits paid from it, so it rises as people settle.

Launch and foreground work runs in `SwiftletApp.refreshBackgroundWork()`: wallet migration, then recurring materialization, then reminder rescheduling.

## Common commands

```bash
xcodegen generate
xcodebuild -project Swiftlet.xcodeproj -scheme Swiftlet -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

```bash
xcodebuild -project Swiftlet.xcodeproj -scheme Swiftlet -destination 'platform=iOS Simulator,id=<iOS 26.5 simulator id>' test -only-testing:SwiftletTests
```

`SwiftletTests` (Swift Testing) is the only test target. Use a simulator id: the deployment target is iOS 26.5, so a device by name can match an older runtime and fail. Swift 5 language mode is on, so write regex literals as `#/.../#`.

## Spec-driven development

`specs/` is the source of truth for what we build and why; read `specs/README.md` first. Write or find a feature spec (`specs/templates/feature.md`) and get it approved before writing code. The `new-feature`, `commit` and `codebase-sync` skills in `.claude/skills/` carry the procedure, and `.claude/rules/commits.md` the commit convention (microcommits). A Stop hook asks for a `codebase-sync` whenever watched source changes; `.claude/sync-state` holds the baseline.
